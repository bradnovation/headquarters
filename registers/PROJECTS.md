# PROJECTS - what this organization runs, and where each stands

*Owned by the Operations seat (`org/seats/operations/CHARTER.md`). This is the
register of record for every project or business you run through this staff.
The short list under `CLAUDE.md`'s generated layer, section (f), is a pointer
here, not a substitute for it - if the two ever disagree, this file is right
and the short list is stale.*

*Format: one H2 section per project, dated at the moment it is written.
Append-only, newest on top, always. When a project's status changes, or a
fact about it needs correcting, append a new dated section rather than
editing the old one - the old section stays as history, the newest section is
the current truth. This is the same discipline `ops/COLD_RESUME.md` asks of
every role-owned record in this repository: a correction is something you
add, never something you erase.*

*Status values, exactly these three words:*

- ***active*** - *live, ordinary work happens here.*
- ***paused*** - *deliberately not being worked right now, not abandoned.*
- ***sunset*** - *wound down on purpose; kept for history, not for action.*

*If none of the three fits what you are trying to record, it is probably a
task rather than a project's standing state - see `registers/TASKS.md`.*

*Cross-reference `registers/TASKS.md` for the work items each project spawns,
and `registers/BLOCKED_ON_OPERATOR.md` for anything about a project only you
can unblock.*

*A fork-posture note, because this register is the first place it usually
bites: once this file names a real project, `doctrine/CONSTITUTION-CORE.md`
classifies that content C1 (internal business), not C0 (public). A public
working copy may hold C0 only - see the fork-posture question in that file's
security-classes section, and the answer you recorded in `CLAUDE.md`'s
generated layer. An empty register, as shipped, is C0 by definition; the
first real entry you add is the moment this file's own classification
changes.*
