# SESSION LOG - the per-session record
<!-- file-class: PERSONAL -->

*This file is yours. It is written by your sessions, it is never
overwritten by an upstream update, and nothing in it ships back anywhere.*

*This file answers one question: **what has actually happened here, session by
session?** `HANDOFF.md` says where things stand now; this says how they got there. It
is the org's memory of its own working life.*

---

## How this file works

**Newest entry on top, append-only below it.** Past entries are never edited to make
history read better. If an entry turns out to be wrong, the correction goes in the
next entry, naming what it corrects.

**One entry per session that changed repo state.** A session that only oriented and
proposed adds nothing here. A session that wrote, ruled, spent, or moved a status
writes an entry, and writes it as part of the park ritual in `ops/OPERABILITY.md`.

**It records, it does not decide.** Rulings belong in `DECISIONS.md`; live state
belongs in `HANDOFF.md`; work status belongs in the registers. This file points at
those and adds the one thing they lack: an honest account of what the session did,
including what it got wrong.

**Cost is part of the record.** Every entry names what the session spent against what
was projected. A log that records only outcomes teaches nothing about what work costs,
and estimating the next run is guesswork without it.

**Failures are recorded plainly.** A session that burned budget on a wrong approach, or
had to be redirected, or shipped something that later needed undoing, says so in its
own entry. This is the only place that record exists, and a log that only contains
successes is a log nobody can learn from.

---

## Entry format

```
## <YYYY-MM-DD> - <short title: what this session was about>

**Route.** Which route from the router was taken: meeting, mission, sweep, dream, park.

**Did.** What landed, each item pointing at the file or artifact that proves it.

**Decided.** Rulings given this session, by number, with a one-line summary each.
Points at `DECISIONS.md`; the full text lives there, not here.

**Spent.** Projected versus actual, and an attribution line for any overage.

**Went wrong.** Anything that failed, was redone, or had to be redirected - and the
lesson if there is one. Write "nothing" only when it is true.

**Left.** What is unfinished, and where the next session picks it up.
```

Keep entries to something a reader can take in at a glance. The log earns its keep by
being readable end to end when someone wants to know how a situation developed.
